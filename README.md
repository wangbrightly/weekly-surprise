# 每周小惊喜

每周随机挑一天，提醒你给她转一笔随机金额的账，并备好一句话。

## 这个应用不做什么

**它不碰任何支付接口。** 微信不对第三方应用开放个人转账能力，所以本应用只负责三件事：到点提醒、把金额和话术准备好、帮你跳到微信。**钱是你自己手动转的。**

如果你在找"自动转账"工具，这里没有，别处也不会有 —— 那个能力不存在。

## 为什么用系统日历而不是自己排闹钟

国产 ROM（尤其小米的 MIUI / HyperOS）会激进地清理后台应用。一个每周才响一次的应用，几乎必然在某次待机中被冻掉，然后你永远不知道它哪天不响了。

所以本应用**不在后台运行**：它一次性把未来 12 周的提醒写进系统日历，到点响铃的是系统日历本身 —— 那是系统应用，不会被自己清理。每次你打开应用，它顺手把存量补满。

这不是更巧妙的斗法，是直接换掉了会输的战场。

## 隐私

- **不联网。** 没有任何网络权限。
- 所有数据只存在手机本地，不上传、不备份到云。
- 只写入**设备本地日历**，绝不写入会同步到云端的账户 —— 否则这些条目可能出现在共享同一账户的其他设备上。
- 日历事件标题是中性的，**不含金额和话术**，翻日历看不出内容。
- 仓库里的话术是通用示例。你自己添加或修改的话术只存在手机上，永远不会进入这个仓库。

## 权限说明

| 权限 | 用途 |
| --- | --- |
| 读写日历 | 写入与清理提醒事件（只碰本应用创建的，不动你自己的日程） |
| 通知（Android 13+） | 应用内的操作提示 |

没有网络权限，没有后台自启，没有读取通讯录或短信。

## 构建

需要 JDK 17 与 Android SDK（platform 36、build-tools 36.1.0）。不需要 Android Studio。

```bash
# 指向你的 SDK
echo "sdk.dir=$HOME/Library/Android/sdk" > local.properties

# 跑测试
gradle test

# 出 APK
gradle assembleDebug
# 产物在 app/build/outputs/apk/debug/app-debug.apk
```

安装到手机（需先开启开发者选项与 USB 调试）：

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

**注意**：本项目使用 AGP 9，Kotlin 支持已内置。**不要**添加 `org.jetbrains.kotlin.android` 插件，加了会直接构建失败。

## 测试

核心逻辑（抽日、金额、话术、去重）全部与安卓框架解耦，可在电脑上直接跑：

```bash
gradle test
```

覆盖的关键约束：

- 每个自然周恰好一次提醒
- 任意两次提醒相隔不少于 4 天（避免"周日 + 次周一"这种不像每周一次的排布）
- 金额始终落在设定区间内
- 话术连续 8 次内不重复，且话术库容量不得低于窗口的 3 倍
- 重复补足不产生重复日历事件
- 写入日历的文本不含任何数字（防止金额泄露）

## 验证提醒是否真的会响

分两级，别把第一级当第二级：

1. **链路验证**：应用内"写入一条 2 分钟后的测试提醒"，走的是与真实提醒完全相同的写入路径。
2. **存活验证**：链路通不等于久置后仍会响。用 `adb shell dumpsys deviceidle force-idle` 强制进入 Doze 后观察，或直接放置一晚。

如果到点没响，先查系统「日历」应用的通知是否被关闭 —— 响铃归它管，不归本应用管。
